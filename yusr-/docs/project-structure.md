# هيكل مشروع يُسر بالتفصيل

هذا الملف يشرح بنية تطبيق **يُسر** حتى يسهل تطويره، تسليمه، رفعه، أو تحويله لاحقًا إلى تطبيق هاتف.

التطبيق مبني بملفات ثابتة:

- HTML
- CSS
- JavaScript Modules
- PWA
- تخزين محلي
- Supabase اختياري للتفعيل والأكواد والمزامنة

## 1. ملفات الجذر

### `index.html`

نقطة دخول التطبيق.

مسؤول عن:

- تحميل ملف التصميم الرئيسي.
- تحميل `app.js`.
- تعريف عناصر التطبيق العامة مثل الشريط الجانبي، الشريط العلوي، النافذة، والتنبيهات.
- ربط Manifest الخاص بالـ PWA.

### `app.js`

قلب التطبيق.

مسؤول عن:

- إنشاء الخدمات الأساسية.
- تشغيل الصفحات.
- التنقل بين المسارات.
- صفحة التفعيل وطرق الدفع.
- شاشة كلمة السر.
- قسم المشرف.
- إشعارات التطبيق الذكية.
- ربط المساعد الذكي.
- تطبيق الصلاحيات حسب نوع الحساب.

أهم المسارات فيه:

- `#/activate`: صفحة التفعيل.
- `#/home`: الرئيسية.
- `#/subjects`: المواد.
- `#/subject/:id/students`: طلاب المادة.
- `#/subject/:id/attendance`: التحضير.
- `#/subject/:id/sheet`: الكشف.
- `#/subject/:id/grades`: الدرجات.
- `#/subject/:id/stats`: إحصائيات المادة.
- `#/schedule`: الحصص.
- `#/manager`: قسم المشرف.
- `#/admin`: لوحة صاحب التطبيق.
- `#/settings`: الإعدادات.

### `styles.css`

التصميم الأساسي.

يشمل:

- الثيم الفاتح والداكن.
- RTL.
- صفحة التفعيل.
- صفحة الدفع.
- الروبوت والمساعد الذكي.
- الجداول.
- بطاقات المواد.
- قسم المشرف.
- السلوك والمواظبة.
- التقارير.
- تصميم الجوال واللابتوب.

### `manifest.webmanifest`

ملف تثبيت التطبيق كتطبيق PWA.

يحدد:

- اسم التطبيق.
- الأيقونات.
- لون التطبيق.
- طريقة الفتح.
- اتجاه التطبيق.

### `sw.js`

Service Worker.

مسؤول عن:

- حفظ الملفات الأساسية.
- تشغيل التطبيق بدون إنترنت بعد أول تحميل.
- تحديث الكاش عند رفع نسخة جديدة.

### `supabase-config.js`

إعدادات Supabase.

يحتوي على:

- رابط المشروع.
- المفتاح العام.

يُستخدم في:

- أكواد التفعيل.
- طلبات التفعيل.
- الأكواد التابعة.
- مزامنة بيانات الحسابات التابعة.
- الأسعار.

### `firebase-config.js`

ملف إعداد Firebase احتياطي.

موجود لأن النسخة الأولى كانت تدعم Firebase، لكن الاعتماد الحالي في الحماية والتفعيل على Supabase.

## 11. تدفق التفعيل

1. يفتح المستخدم التطبيق.
2. تظهر صفحة التفعيل.
3. يختار استخدام مجاني أو طلب التفعيل.
4. عند طلب التفعيل يختار:
   - نوع الحساب.
   - نوع الاشتراك.
   - طريقة الدفع.
5. يكتب اسم المحول.
6. يضغط تم الدفع.
7. يتم إنشاء كود مؤقت لمدة يوم.
8. يظهر الطلب في لوحة الأدمن.
9. صاحب التطبيق يعتمد الطلب.
10. يتحول الكود إلى اشتراك رسمي.

إذا حاول المستخدم الدفع مرة ثانية بعد كود مؤقت غير معتمد:

- لا يفتح التطبيق مباشرة.
- ينتقل الطلب إلى قسم تحقق من الدفع.
- صاحب التطبيق هو من يسمح بالتفعيل.

## 12. تدفق الحسابات التابعة

1. المشرف يفعّل حسابه.
2. يدخل قسم المشرف.
3. ينشئ كودًا تابعًا لمعلم أو مندوب.
4. يحدد الصلاحيات.
5. المعلم أو المندوب يدخل بالكود.
6. بياناته تتزامن مع المشرف عند توفر Supabase.
7. المشرف يستطيع فتح صفحة الحساب التابع ومتابعة بياناته.

## 13. تدفق التحضير

1. المستخدم يفتح المادة.
2. يختار اليوم.
3. يختار الحصة.
4. يحدد حالة الطلاب.
5. يحفظ التحضير.
6. يظهر التحضير لاحقًا في الكشف الشهري حسب اليوم والحصة.

## 14. تدفق الدرجات

1. يفتح قسم الدرجات.
2. يضيف أعمدة حسب نظامه.
3. يحدد الدرجة العظمى.
4. يدخل درجات الطلاب.
5. التطبيق يمنع تجاوز الدرجة العظمى.
6. المجموع يحسب تلقائيًا.
7. يمكن تصدير الدرجات PDF.

## 15. تدفق السلوك والمواظبة

1. المشرف يفتح قسم المشرف.
2. يدخل السلوك والمواظبة.
3. يختار الجهة والمادة والمعلم والطالب.
4. يسجل المخالفة والإجراء.
5. يمكن ربط الحسم بعمود السلوك.
6. تظهر المخالفة في سجل الطالب.
7. يمكن تصدير PDF خاص بمخالفات الطالب.

## 16. ملاحظات تطوير مهمة

- لا تغيّر أسماء مفاتيح التخزين المحلي دون عمل ترحيل للبيانات.
- عند تعديل `app.js` أو الخدمات، ارفع رقم النسخة في `index.html` و`sw.js` لتحديث الكاش.
- عند إضافة عمود جديد في Supabase، أضفه أيضًا في `docs/supabase-licenses.sql`.
- عند إضافة صلاحية جديدة، حدث ملفات `roles` ومواضع التحقق داخل الصفحات.
- عند إضافة قسم جديد، حدّث المساعد الذكي وزر المساعدة حتى يفهم المستخدم الغرض منه.
